Discover from servers

Enter the IP addresses of one environment's servers (web, app, process scheduler). The dashboard connects with your SSH user and key, finds the PeopleSoft owner, PS_HOME and every domain, and fills in the rows for you. Nothing is changed on the servers.

Import environments

Paste rows from Excel or a CSV, or drop a .csv file in the box. One row per server; rows with the same environment are grouped. Importing an environment that already exists replaces its rows. The previous file is backed up first.

Columns

Required: environment, host. For start/stop: role (web, app or prcs) and domain.
Optional: client, tier (PRD environments ask for confirmation before stop), ip, os_user (the PeopleSoft owner, e.g. psadm2, used with sudo when it differs from your SSH user), env_script (path to psconfig.sh, sourced before psadmin), pt_home, java_home, weblogic_home, and per-server ssh_user, ssh_key, ssh_port to override your sign-in values.

Patch levels

Reads WebLogic, JDK, Oracle Database Client and Tuxedo levels live from every server and compares them with the latest patches on Oracle Support (and Oracle Java releases for the JDK). CPU targets are optional overrides. Read-only.

Files go to <staging folder>/<label>/ on each server that needs them, written as that server's PeopleSoft owner and checked with SHA-256. Patches are downloaded once into the dashboard's data\patches\<patch number> folder and reused. If a download from Oracle Support doesn't work, put the zip in that folder yourself and stage again.

Change approval (Jira)

When this is on, an Apply button first raises a Jira ticket describing exactly what will be patched, on which servers, the outage and the backout. Apply unlocks only when the ticket is in an approved status, approved by someone other than the Jira account below. Pegasus checks Jira again at the moment you apply, each approval is used once, and the result is posted back to the ticket.

CPU targets

JDK is automatic: with no JDK row, each server is compared with Oracle's latest JDK release for its version (from Oracle's public Java release service) and the tarball is downloaded from Oracle's Java download service. Add a JDK row only to pin a specific version. WebLogic and Tuxedo patch numbers are published only on My Oracle Support, so add those each quarter.

One row per component and version line. Update these each quarter from Oracle's CPU advisory and the PeopleSoft certification notes.
JDK: target is a version (e.g. 21.0.12); hosts below it need the patch. WebLogic: target is the patch number(s) that must show in opatch lspatches, space separated. Tuxedo: target is the rolling patch level (e.g. 051).
Applies to limits a row to one version line (e.g. 21, 14.1.2.0, 22.1.0.0.0). MOS patch is the number to download. Platform defaults to 226P (Linux x86-64) for JDK and Tuxedo and 2000P (Generic) for WebLogic. File filter is an optional pattern to pick one file when a patch has several, e.g. 141200.

Give or remove SSH access

Adds a person's public key to authorized_keys on every server in the environments you choose, over your SSH connection. Pegasus backs up the file first, never adds the same key twice, and leaves the other keys alone.

Leave the account blank to use your SSH user, usually opc, which has sudo. For another account such as psadm1, your SSH user needs a passwordless sudo rule for it.
